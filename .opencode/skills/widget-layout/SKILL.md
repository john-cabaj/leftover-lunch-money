# Widget Layout

Layout and sizing spec for the renderers in `index.js`. Apply these rules before touching `renderWidget`, `FAMILY_LAYOUTS`, `addTextRow`, `rowFitHeight`, `widgetSizes`, `listHeightBudget`, or any family/size constant. WidgetKit quirks here are device-verified, not theoretical.

## FAMILY_LAYOUTS

`FAMILY_LAYOUTS` holds one config per widget family (`small` / `medium` / `large` / `extraLarge` / `accessoryRectangular` / `accessoryCircular` / `accessoryInline`) plus an `undefined` fallback. Each config names its `layout` and a single `amount` size (all three money rows share one size), plus layout-specific fonts/caps (`caption`, `detailFont`, `payeeLen`) and per-layout `topPad` (small) / `headerPad` + `headerGap` (medium) / `padTop` + `padBottom` + `padSide` (accessory). The accessory circular layout shows a "Leftover" caption (9pt) above the amount (13pt), both fixed in the config and centered; the caption must stay smaller than the amount so the stacked pair fits the ring on every device. This fixed sizing replaced the older per-render fit test.

`FAMILY_LAYOUTS` uses one `amount` size for all three money rows; layouts pick their own row ORDER — don't reintroduce per-metric-size duplication.

## Paddings and gaps

Standard top/bottom padding is 14pt (`TOP_PAD`). The small widget uses a tighter 10pt `topPad`; the medium widget pushes its title down with a 6pt `headerPad` and closes the title→period gap with a 0pt `headerGap`. The header block nests title + period in its own stack so `headerGap` can differ from the mainStack spacing; `headerHeight` stays in sync via `headerBlockGap`/`headerBlockHeight`. No small-widget padding is touched for the Delete Pending label — it sits inside the small layout's ordinary margins (bottom padding stays 14pt), riding the widget's real on-device slack.

Layout gaps are named constants (`REVIEW_GAP`, `OVERVIEW_GAP`, `LIST_BODY_GAP`) used in BOTH the renderers (`renderWidget`, `addOverview`, `addBreakdownSection`) and `listHeightBudget`, so a gap tweak never desyncs the rendered spacer from the row-fit math. Always update both sites together.

## Title centering

The title row centers LUNCH MONEY: an invisible mirror of the timestamp balances the timestamp + gap on the left while the two flexible spacers share the rest, so centering never shifts whether or not the time renders.

## Delete Pending badge rendering

The Delete Pending label shows only on families with an unreviewed list or the small stacked widget (small / medium / large / extraLarge, plus the mid-size lock-screen widget — accessoryRectangular, whose badge sits left-aligned above the "Unreviewed Transactions" caption exactly like the medium's) and only when the displayed period has delete_pending transactions. It renders at the same size and weight as the caption labels (Inflow / Outflow / Leftover / Unreviewed — `config.caption`) in the palette's `LOSS_RED` (the rectangular accessory overrides it with the label color `brandYellow` — on lock screens labels are one color, amounts another — so only the home screens show the red), as one tappable line ("Deleted Transactions Pending", `BADGE_PENDING_LABEL`) at the top of the unreviewed list column — above the "Unreviewed Transactions" caption — in the shared `addUnreviewedSection` (used by `addOverview`, `addReviewSplit`, and `addAccessoryRectangular`, delegating to `addDeletePendingBadge`), aligned the way that caption is: centered on large, left-aligned on medium and on the rectangular accessory, via `addTextRow` — the accessory additionally stretches the badge row across the column (and the Unreviewed caption) so the text pins to the same flush-left edge as the transaction rows: WidgetKit's lock-screen stacks center natural-width children, which would otherwise float the caption and badge a few points to the right of the rows. The transaction rows themselves then take a `MENLO_LEFT_INSET` leading nudge so their monospaced first glyphs share the Avenir caption's visual left edge (the two faces render their left bearing differently); the inset is a device-calibration constant.

Because the label lives inside the list column rather than the header, `headerHeight` is untouched; `listHeightBudget` (and therefore the fitted row counts in `maxUnreviewedCount`) instead reserves the badge's line plus `LIST_BOTTOM_SLACK` (2pt, the same slack the review layout already builds into `WIDGET_HEIGHTS`) via `deletePendingBadgeHeight` whenever the label shows, so the list loses part of one row while it's up — the rectangular accessory's budget subtracts the same reserve before the rows, so a Delete Pending period costs it part of one row too — exactly "taking the space of some of those transactions" — and never sits flush against the widget's height limit (a flush list can clip the top of the widget). Tap routing: the badge's own URL is honoured on the rectangular accessory exactly as on the home screens, because no ancestor stack sets a URL (the column has none; the unreviewed URL sits on the caption row and the list stack, matching the project's "limit unreviewed tap target to the label and list rows" convention). The line keeps the caption's exact font and size (no `minimumScaleFactor` — it fits the narrowest list column, ~188pt on the SE 1st-gen medium vs ≈186pt for the label at 13pt, and ≈143pt at the rectangular accessory's 10pt caption vs its 145pt inner width, so it never needs to shrink) and stays on one line.

The small stacked widget fits the same full badge line instead — the whole "Deleted Transactions Pending!" at the caption's size and weight (one `addDeletePendingBadge` call, left-aligned like the metric captions) sat on top of the Inflow/Outflow/Leftover stack (`addStackedMetrics`), replacing the old lone "!" that rode the Leftover amount row. It rides the widget's real on-device slack: WidgetKit lays the Avenir caption lines tighter than the measured `Font.lineHeight` heights the amount fit reserves against, and the budget's own 2pt + padding-math slack add up to ~11pt — just over the label's lean box — so no size, padding, or amount fit changes. On small the label is display-only (a small widget has a single tap target, so only `widget.url` — Budget — fires; this replaced the razor-thin "!" that was both unreadable as a label and never tappable anyway). The line's measurements (`BADGE_PENDING_LABEL`, `LIST_BOTTOM_SLACK`, `deletePendingBadgeHeight`) are named constants.

## Sizing and row-fit math

Widget sizes come from `widgetSizes()` (keyed by longest device screen side, with X-class fallback) so budgets scale per device. Row pitches are measured from REAL rendered line heights — `lineHeight` queries Scriptable's `Font.lineHeight` for Avenir, `monoRegularLineHeight` for the Menlo transaction rows, and `monoLineHeight` (Menlo-Bold) for the money amounts — so rows never overflow the bottom edge (overflow pushes content off the TOP of the widget, which once clipped the LUNCH MONEY title). BUT WidgetKit layers text tighter than `Font.lineHeight`, which is the visible slack on device; the review layout reserves its fixed header + caption at the lean box (`leanLineHeight`, `LEAN_LINE_FACTOR`) to use that slack. One rule governs the small stacked badge: nothing may overflow, because an overflowing element makes WidgetKit scale the ENTIRE widget down (the "everything looks smaller" failure mode). The label only fits because it occupies the widget's real slack instead of consuming space of its own — WidgetKit lays the Avenir title/caption lines tighter than the measured `Font.lineHeight` heights the amount fit reserves against — so the badge never crowds the last row or the LUNCH MONEY title. Rough medium counts with this mix (device-verified pitch: Menlo 11 → 13 + ROW_GAP 1 = 14pt): 6 rows at 158pt and 5 rows at 148–155pt with no badge; a Delete Pending badge costs about one row (5 at 158pt, 4 at 148–155pt, 3 on the SE 1st gen) — keep an eye on the LUNCH MONEY title for top-clip.

The medium review list and the row-fit function must stay in lockstep: `addTransactionRow` ends with a trailing `ROW_GAP` spacer that `rowFitHeight` reserves (`monoRegularLineHeight(detailFont(config)) + ROW_GAP` — rows render in regular Monospaced Menlo, so the pitch measures that exact font; Menlo-Bold (the amounts) is `monoLineHeight`, never Avenir's `lineHeight`, which would over-reserve ~2pt a row).

## Metrics and width constants

`METRICS` is the single source for the three money rows (label, value closure, sign color); `addMetrics`, `addMetricRow`, and `addBreakdown` all render from it, so layouts only choose row order and one `amount` size. Leftover's color is decided in `addAmount` (green when positive, red when negative).

Inner widths come from `WIDGET_INNER_WIDTH` (container width minus the 10pt side padding). The medium review split uses `METRICS_WEIGHT`/`LIST_WEIGHT` (31/69 — layoutWeight units summing to 100) and `LIST_COLUMN_WIDTH` for the list column.

Secondary text derives from one size source, `detailFontSize(config[, fallback])`; `timestampFont` and the failed-unreviewed hint subtract from it, so a size tweak lands everywhere.

## Verification and calibration

Functional behavior must be verified on an iOS device via Scriptable (widget families: small / medium / large / extraLarge / accessoryCircular / accessoryRectangular / accessoryInline; the SE 1st gen has no lock-screen widgets and falls back to the X-class accessory spec).

Row budgets measure the REAL `Font.lineHeight` per family (Avenir `lineHeight`, Menlo `monoRegularLineHeight`, Menlo-Bold `monoLineHeight`); on runtimes without `Font.lineHeight` the shipped fallback factors (`AVENIR_LINE_HEIGHT_FALLBACK`, `LINE_HEIGHT_FACTOR`, `LEAN_LINE_FACTOR`) cover the same values, and WidgetKit layers text tighter than `Font.lineHeight`. When a fitted row count or the small-widget badge line is off on a device, these constants (and `MENLO_LEFT_INSET`) are the calibration knobs to adjust.

The layout fit math is ALSO regression-tested headlessly, so silent drift fails `node --test` instead of needing an eye on a phone: `test/pure-core.test.js` slices `index.js` and re-runs the layout regions per known iPhone screen height with a stub `Device.screenSize()` and a `Font` stub with no `.lineHeight` (so the shipped fallback factors apply). The "widget layout (deterministic fit math)" spec pins the device tables (`widgetSizes` / `ACCESSORY_SPECS` rows per screen height), the row pitches (Menlo 11 → 13 + `ROW_GAP` 1 = 14pt et al.), the badge reserves (`leanLineHeight(caption) + LIST_BOTTOM_SLACK`), the fitted row counts (`Math.floor(budget / pitch)`), `smallAmountFont`, and the "rows never overflow the budget" invariant. These are the FALLBACK-MATRIX values — Node cannot see WidgetKit, so the device-verified counts in this skill stay authoritative: when you turn a calibration knob, update `index.js`, the pinned matrices in the spec, AND re-verify on device.

Keep every size/measurement a named constant; row budgets derive from the real widget container size so lists never overflow.
